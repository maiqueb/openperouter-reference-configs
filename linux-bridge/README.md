# Linux Bridge 
Reference configurations for connecting KubeVirt VMs to an EVPN L2 VNI, using linux-bridge attachments.
- `00-vni-linux-bridge-nncp.yaml` - NodeNetworkConfigurationPolicy creating the linux-bridge.
- `01-openperouter-underlay.yaml` - OpenPERouter EVPN underlay configs.
- `02-openperouter-vnis.yaml` - OpenPERouter EVPN VNI configs.
- `03-vni-linux-bridge-nad.yaml` - Linux-bridge NetworkAttachmentDefinition.
- `04-workloads.yaml` - KubeVirt VMs example.

The underlay is a macvlan `CNIDevice` created by OpenPERouter (via the CNI
plugin) on top of the node NIC (`ens4`, net1), inside the router network
namespace. The node NIC is never moved out of the host, and each node's address
is assigned through static IPAM, so one `Underlay` object is needed per node.

> **Note**: Manifests are generated by the scripts below from `test/env.sh`
> and the templates in `templates/`.

# Testing
The scripts assume the following podman networks already exist:

| Network | Subnet | Purpose |
|---|---|---|
| `default-network` | `192.168.122.0/24` | libvirt default network (not used by BGP) |
| `net1-ext` | `10.200.0.0/16` | EVPN underlay; the router address is discovered at setup |
| `my-isolated-network` | `192.169.1.0/24` | external router <-> external client |

## `test/env.sh`
All parameters live here: node names, underlay addresses, external router
address, VM IPs and SSH keys. Adjust it to your environment.

The worker node names default to `multi-homing-worker-0.maiqueb.org` and
`multi-homing-worker-1.maiqueb.org`. Override them with `--node0`/`--node1`
(or the `NODE0`/`NODE1` environment variables); the short hostname used in the
`Underlay` object names is derived from the first label of each FQDN:

```bash
./test/setup.sh --node0 worker-a.example.com --node1 worker-b.example.com
./test/test.sh  --node0 worker-a.example.com --node1 worker-b.example.com --restart-vms
```

## `test/setup.sh`
- Builds the external-router image from `../external-router/Containerfile`.
- Starts the external router with:

  ```bash
  podman run -d --privileged \
      --network default-network --network net1-ext --network my-isolated-network \
      --rm --ulimit core=-1 --name frr \
      --volume "$FRR_CONFIG":/etc/frr frr-router
  ```

  The entrypoint puts the external-client NIC (`eth2`, `my-isolated-network`)
  into VRF `red`; `eth1` (`net1-ext`) stays in the default VRF for BGP. If
  podman names the NICs differently, set `CLIENT_NIC`.
- Reads the router's two addresses with `podman inspect`: the `net1-ext`
  address becomes the `Underlay` BGP neighbor, and the
  `my-isolated-network` address (the `net2`/`eth2` attachment, e.g.
  `192.169.1.26`) becomes the external client's default gateway.
- Starts the external client and, in the same `podman run`, replaces its
  default route with `default via <external-router>`.
- Renders and applies the NNCP, `Underlay` and VNI manifests, waits for BGP
  convergence, and writes `test/setup.log`.

## `test/test.sh`
- Renders the NAD and VM manifests and deploys them.
- Tests VM <-> VM, VM <-> external router (VRF `red`), and VM <-> external
  client connectivity.
- Supports `--restart-vms`; results go to `test/test-result-summary.txt`.

## `test/cleanup.sh`
Removes the containers, OpenPERouter CRs, NNCP and test namespace. The podman
networks are lab infrastructure and are left in place.

## Debugging
`results/gen-router-reports.sh` generates network and routing state reports for
the worker nodes, the external router, and the external client under `results/`.

### Example
Initial run:
```bash
$ ./test/setup.sh && ./test/test.sh && ./results/gen-router-reports.sh
```
Re-run tests after a VM / NAD change:
```bash
$ ./test/test.sh --restart-vms
```
Start fresh:
```bash
$ ./test/cleanup.sh && ./test/setup.sh && ./test/test.sh && ./results/gen-router-reports.sh
```
