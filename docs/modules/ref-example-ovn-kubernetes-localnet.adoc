= Complete example: OVN-Kubernetes localnet with a dedicated bridge

[role="_abstract"]
The following manifests implement the dedicated bridge model: a kernel bond
for the underlay, an OVS bridge for the OVN-Kubernetes localnet, an EVPN L2VNI
and L3VNI, a localnet `ClusterUserDefinedNetwork`, and two virtual machines on
different nodes.

The NNCP and virtual machine manifests are based on
`localnet/dedicated-bridge/` and are usable as-is after you replace the node
names and addresses. The network attachment is expressed as a
`ClusterUserDefinedNetwork`, so OVN-Kubernetes creates the corresponding
`NetworkAttachmentDefinition`. The OpenPERouter resources are converted from the legacy
`openpe.openperouter.github.io/v1alpha1` API to
`network.openperouter.io/v1alpha1`. The external router configuration is
adapted from `linux-bridge/external-router/` because the dedicated bridge
directory does not include a router artifact.

== Node network configuration

[source,yaml]
----
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: dedicated-linux-bond-iface
spec:
  nodeSelector:
    node-role.kubernetes.io/worker: ""
  desiredState:
    interfaces:
      - name: bond1
        type: bond
        state: up
        ipv4:
          enabled: false
        ipv6:
          enabled: false
        link-aggregation:
          mode: active-backup
          port:
            - ens4
            - ens5
      - name: ens4
        type: ethernet
        state: up
      - name: ens5
        type: ethernet
        state: up
      - name: ovsbr1
        type: ovs-interface
        state: up
        ipv4:
          enabled: false
        ipv6:
          enabled: false
      - name: ovsbr1
        type: ovs-bridge
        state: up
        bridge:
          allow-extra-patch-ports: true
          options:
            stp: false
          port:
            - name: ovsbr1
    ovn:
      bridge-mappings:
        - bridge: ovsbr1
          localnet: datanet
          state: present
----

This policy creates a kernel bond from `ens4` and `ens5` and an OVS bridge
named `ovsbr1` with no uplink. OVN-Kubernetes adds its patch port to
`ovsbr1`, and the bridge mapping associates the bridge with the localnet name
`datanet`.

The alternative file `nncp-balance-slb.yaml` creates an OVS bond in
`balance-slb` mode inside `ovsbr1`. Use one variant only. An OVS bond is not a
kernel network device, so the underlay macvlan cannot use it as a parent.

== Localnet network attachment

[source,yaml]
----
apiVersion: k8s.ovn.org/v1
kind: ClusterUserDefinedNetwork
metadata:
  name: evpn
spec:
  namespaceSelector:
    matchLabels:
      kubernetes.io/metadata.name: default
  network:
    topology: Localnet
    localnet:
      role: Secondary
      physicalNetworkName: datanet
      ipam:
        mode: Disabled
----

`ipam.mode: Disabled` makes OVN-Kubernetes assign only a MAC address and
leave IP configuration to the workload. The virtual machines below set their
own static addresses through cloud-init, and OpenPERouter provides the anycast
gateway. The OVN-Kubernetes controller creates a
`NetworkAttachmentDefinition` named `evpn` in the `default` namespace, so the
`default/evpn` network name in the virtual machine manifests still applies.

assigns the pod interface MAC, and the localnet path enforces MAC spoof
checking.

== External router, adapted

The dedicated bridge directory has no router artifact. The following
configuration is adapted from `linux-bridge/external-router/network-setup.sh`.
It creates the VTEP loopback, the `red` VRF, the L3VNI, and the VXLAN
interfaces:

[source,bash]
----
ip addr add 100.64.0.1/32 dev lo
ip link add red type vrf table 1100
ip link set <external-client-nic> master red
ip link set red up

ip link add br100 type bridge
ip link set br100 master red addrgenmode none
ip link set br100 addr aa:bb:cc:00:00:65
ip link add vni100 type vxlan local 100.64.0.1 dstport 4789 id 100 nolearning
ip link set vni100 master br100 addrgenmode none
ip link set vni100 type bridge_slave neigh_suppress on learning off
ip link set vni100 up
ip link set br100 up

ip link add vni110 type vxlan local 100.64.0.1 dstport 4789 id 110 nolearning
ip link add br110 type bridge
ip link set br110 master red addrgenmode none
ip link set vni110 master br110
ip link set vni110 type bridge_slave neigh_suppress on learning off
ip link set vni110 up
ip link set br110 up
ip addr add 192.170.1.100/24 dev br110
----

The adapted FRR configuration peers with the cluster over `10.200.0.0/16`:

[source,frr]
----
vrf red
 vni 100
exit-vrf

router bgp 64512 vrf red
 address-family ipv4 unicast
  redistribute connected
 exit-address-family
 address-family l2vpn evpn
  advertise ipv4 unicast
  advertise ipv6 unicast
 exit-address-family
exit

router bgp 64512
 no bgp ebgp-requires-policy
 no bgp network import-check
 no bgp default ipv4-unicast
 neighbor ocp-nodes peer-group
 neighbor ocp-nodes remote-as 64514
 bgp listen range 10.200.0.0/16 peer-group ocp-nodes
 address-family ipv4 unicast
  network 100.64.0.1/32
  neighbor ocp-nodes activate
 exit-address-family
 address-family l2vpn evpn
  neighbor ocp-nodes activate
  neighbor ocp-nodes allowas-in origin
  advertise-all-vni
  advertise-svi-ip
 exit-address-family
exit
----

== Teardown

Delete the workloads and attachments first, then the VNIs, the Underlay, and
the NNCP:

[source,terminal]
----
$ oc delete vm vm-1 vm-2 -n default
$ oc delete clusteruserdefinednetwork evpn
$ oc delete l2vni layer2 l3vni red -n openperouter-system
$ oc delete underlay underlay-worker0 underlay-worker1 -n openperouter-system
$ oc delete nncp dedicated-linux-bond-iface
----

Deleting the NNCP removes `ovsbr1` and the bridge mapping from the nodes.
Confirm that no workload still uses the bridge before you delete the policy.
