= Workload bridge

[role="_abstract"]
The workload bridge is the host side of the Layer 2 segment. Kubernetes
NMState creates the bridge, the `L2VNI` attaches to it with
`lifecycle: External`, and workloads attach through an OVN-Kubernetes localnet
or a bridge network attachment. The workload bridge does not carry the
underlay.

.Prerequisites

* The uplink is configured and the external router is reachable from the node
  underlay addresses.
* The Kubernetes NMState Operator and OpenPERouter are installed.
* You have decided on the VNI identifiers, the workload subnet, and the
  anycast gateway address.
* For the Linux bridge model, OpenShift Virtualization is installed.

== OVN-Kubernetes localnet

Create an OVS bridge, map it to a localnet name, and create a
`ClusterUserDefinedNetwork` that requests that localnet. OVN-Kubernetes owns the
workload attachment; OpenPERouter provides the EVPN stretch and the anycast
gateway.

. Create the OVS bridge and the OVN-Kubernetes bridge mapping. The bridge has no
uplink because VXLAN carries the workload segment. The
`allow-extra-patch-ports` option lets OVN-Kubernetes add its patch port, and
STP must be disabled:
+
[source,yaml]
----
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: localnet-dedicated-bridge
spec:
  nodeSelector:
    node-role.kubernetes.io/worker: ""
  desiredState:
    interfaces:
      - name: ovsbr1
        type: ovs-interface
        state: up
        ipv4:
          enabled: false
        ipv6:
          enabled: false
      - name: ovsbr1
        type: ovs-bridge
        state: up
        bridge:
          allow-extra-patch-ports: true
          options:
            stp: false
          port:
            - name: ovsbr1
    ovn:
      bridge-mappings:
        - bridge: ovsbr1
          localnet: datanet
          state: present
----

. Create the localnet `ClusterUserDefinedNetwork`. The
`localnet.physicalNetworkName` value must match the `localnet` value in the
bridge mapping. `ipam.mode: Disabled` leaves IP configuration to the workload:
+
[source,yaml]
----
apiVersion: k8s.ovn.org/v1
kind: ClusterUserDefinedNetwork
metadata:
  name: evpn
spec:
  namespaceSelector:
    matchLabels:
      kubernetes.io/metadata.name: default
  network:
    topology: Localnet
    localnet:
      role: Secondary
      physicalNetworkName: datanet
      ipam:
        mode: Disabled
----

. Point the `L2VNI` at the bridge. The `L2VNI` is the OpenPERouter resource
that references the workload bridge; the `Underlay` still attaches to the node
NIC or to `br-ex`, not to this bridge:
+
[source,yaml]
----
apiVersion: network.openperouter.io/v1alpha1
kind: L2VNI
metadata:
  name: layer2
  namespace: openshift-openperouter
spec:
  vni: 110
  hostMaster:
    type: OVSBridge
    ovsBridge:
      lifecycle: External
      name: ovsbr1
  gatewayIPs:
    - 192.170.1.1/24
  routingDomain:
    type: L3VNI
    l3vni:
      name: red
----

. Create the virtual machine and request the localnet network. OVN-Kubernetes
creates a `NetworkAttachmentDefinition` named after the
`ClusterUserDefinedNetwork` in the matching namespace:
+
[source,yaml]
----
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: vm-1
  namespace: default
spec:
  runStrategy: Always
  template:
    spec:
      domain:
        devices:
          interfaces:
            - bridge: {}
              name: evpn
      networks:
        - multus:
            networkName: default/evpn
          name: evpn
      volumes:
        - name: cloudinitdisk
          cloudInitNoCloud:
            networkData: |
              version: 2
              ethernets:
                eth0:
                  addresses:
                    - 192.170.1.3/24
                  gateway4: 192.170.1.1
----
+
MAC spoof checking is always enabled for the localnet path, so do not configure
a guest MAC address that differs from the MAC that OVN-Kubernetes assigns. If
you need a fixed MAC address, use the Linux bridge model instead.

== Linux bridge

Create a kernel bridge and a `bridge` network attachment. The `L2VNI` attaches
to the kernel bridge with `lifecycle: External`, and the bridge network
attachment gives the virtual machine its local port. This model supports a
fixed guest MAC address and promiscuous mode.

. Create the kernel bridge. The bridge has no IP address and no DHCP client;
OpenPERouter provides the gateway:
+
[source,yaml]
----
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: linux-bridge-perouter-vni-110
spec:
  nodeSelector:
    node-role.kubernetes.io/worker: ""
  desiredState:
    interfaces:
      - name: brvni110
        type: linux-bridge
        state: up
        ipv4:
          enabled: false
          dhcp: false
        bridge:
          options:
            stp:
              enabled: false
----

. Point the `L2VNI` at the kernel bridge:
+
[source,yaml]
----
apiVersion: network.openperouter.io/v1alpha1
kind: L2VNI
metadata:
  name: red-110
  namespace: openshift-openperouter
spec:
  vni: 110
  routingDomain:
    type: L3VNI
    l3vni:
      name: red-100
  gatewayIPs:
    - 192.170.1.1/24
  hostMaster:
    type: LinuxBridge
    linuxBridge:
      lifecycle: External
      name: brvni110
----

. Create the `bridge` network attachment for the virtual machines. The
`k8s.v1.cni.cncf.io/resourceName` annotation is required for KubeVirt bridge
binding, and `macspoofchk: false` allows a fixed guest MAC address:
+
[source,yaml]
----
apiVersion: k8s.cni.cncf.io/v1
kind: NetworkAttachmentDefinition
metadata:
  name: evpn-l2vni-110
  annotations:
    k8s.v1.cni.cncf.io/resourceName: bridge.network.kubevirt.io/brvni110
spec:
  config: |
    {
      "cniVersion": "0.3.1",
      "name": "evpn-l2vni-110",
      "type": "bridge",
      "bridge": "brvni110",
      "ipam": {},
      "macspoofchk": false,
      "preserveDefaultVlan": false,
      "disableContainerInterface": true
    }
----

. Create the virtual machine and request the bridge network attachment:
+
[source,yaml]
----
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: vm-1
  namespace: <namespace>
spec:
  runStrategy: Always
  template:
    spec:
      domain:
        devices:
          interfaces:
            - bridge: {}
              macAddress: 02:79:38:33:33:33
              model: virtio
              name: evpn
              state: up
      networks:
        - multus:
            networkName: evpn-l2vni-110
          name: evpn
      volumes:
        - name: cloudinitdisk
          cloudInitNoCloud:
            networkData: |
              version: 2
              ethernets:
                id0:
                  match:
                    macaddress: "02:79:38:33:33:33"
                  addresses:
                    - 192.170.1.3/24
                  gateway4: 192.170.1.1
----

== Verification

. Confirm that the `NodeNetworkConfigurationPolicy` reports that the bridge and
the bridge mapping were applied on every node:
+
[source,terminal]
----
$ oc get nncp <policy-name> -o yaml
$ oc get nnce -l nmstate.io/policy=<policy-name> -o yaml
----
+
In `status.conditions` of the policy, `Available` must be `True` with reason
`SuccessfullyConfigured`, and `Degraded` must be `False`. Each enactment, one
per matching node, must report `Available: True`.

. Confirm that OpenPERouter accepted the `L2VNI` and attached it to the bridge:
+
[source,terminal]
----
$ oc get routernodeconfigurationstatus -n openshift-openperouter
----
+
Each node must show `READY` as `True` and `DEGRADED` as `False`, with an empty
`status.failedResources`.

. Confirm that the EVPN VNIs are up in the router pod:
+
[source,terminal]
----
$ oc exec -n openshift-openperouter <router-pod> -c frr -- \
    vtysh -c 'show evpn vni'
----
+
The output lists the `L3VNI` VNI as `L3` and the `L2VNI` VNI as `L2` in the
tenant VRF.

. For the OVN-Kubernetes localnet model, confirm that the
`ClusterUserDefinedNetwork` created its network attachment:
+
[source,terminal]
----
$ oc get clusteruserdefinednetwork evpn -o yaml
----
+
In `status.conditions`, the `NetworkCreated` condition must be `True` with
reason `NetworkAttachmentDefinitionCreated`.
