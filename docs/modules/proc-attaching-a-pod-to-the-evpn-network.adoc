= Attaching a pod to the EVPN network

[role="_abstract"]
Attach a pod to an OVN-Kubernetes localnet network that OpenPERouter stretches
with EVPN. The pod receives a secondary interface from Multus; its primary
interface remains on the default cluster network.

.Prerequisites

* You have created an OVN-Kubernetes localnet NAD, using either the dedicated
  bridge or the shared single NIC procedure.
* The NAD is in the same namespace as the pod, or the pod annotation uses the
  fully qualified `<namespace>/<name>` form.
* The pod can be scheduled on a node that has the localnet bridge and the
  OpenPERouter router pod.
* You have static addresses for the pod that are unique in the workload
  subnet and outside the anycast gateway address.

.Procedure

. Create the pod and attach the localnet NAD with the
`k8s.v1.cni.cncf.io/networks` annotation:
+
[source,yaml]
----
apiVersion: v1
kind: Pod
metadata:
  name: test-localnet-w1
  namespace: evpn-localnet-test
  annotations:
    k8s.v1.cni.cncf.io/networks: '[{"name": "evpn", "ips": ["192.170.1.10/24"], "default-route": ["192.170.1.1"]}]'
spec:
  nodeName: <worker-node-1>
  containers:
    - name: test
      image: nicolaka/netshoot
      command: ["sleep", "infinity"]
----
+
The `ips` value assigns the secondary interface address. OVN-Kubernetes
localnet does not provide an address pool in this configuration, so the
example supplies a static address. The `default-route` value sets the anycast
gateway as the default route for the pod. Omit `default-route` if the pod
must keep the cluster network as its default route.

. For a dual-stack or IPv6 attachment, add an IPv6 address to the same
annotation:
+
[source,yaml]
----
    k8s.v1.cni.cncf.io/networks: '[{"name": "evpn", "ips": ["192.170.1.10/24", "fd00::a:1/64"], "default-route": ["192.170.1.1"]}]'
----
+
IPv6 EVPN requires a kernel and an FRR version with the relevant support.
The reference environment uses kernel 5.18 or later.

. Apply the pod:
+
[source,terminal]
----
$ oc apply -f pod.yaml
$ oc get pod test-localnet-w1 -o wide
----

. Create a second pod on a different node so that the traffic crosses the
VXLAN tunnel:
+
[source,yaml]
----
apiVersion: v1
kind: Pod
metadata:
  name: test-localnet-w2
  namespace: evpn-localnet-test
  annotations:
    k8s.v1.cni.cncf.io/networks: '[{"name": "evpn", "ips": ["192.170.1.20/24"], "default-route": ["192.170.1.1"]}]'
spec:
  nodeName: <worker-node-2>
  containers:
    - name: test
      image: nicolaka/netshoot
      command: ["sleep", "infinity"]
----

.Verification

. Confirm that the pod has the secondary interface:
+
[source,terminal]
----
$ oc exec -n evpn-localnet-test test-localnet-w1 -- ip addr show net1
$ oc exec -n evpn-localnet-test test-localnet-w1 -- ip route
----
+
The interface must have the address from the annotation, and the default
route must use the anycast gateway.

. Confirm connectivity between the two pods:
+
[source,terminal]
----
$ oc exec -n evpn-localnet-test test-localnet-w1 -- \
    ping -c 3 192.170.1.20
$ oc exec -n evpn-localnet-test test-localnet-w2 -- \
    ping -c 3 192.170.1.10
----

. Confirm that the node learned the pod MAC on the localnet bridge:
+
[source,terminal]
----
$ oc debug node/<worker-node-1> -- chroot /host \
    ovs-appctl fdb/show ovsbr1
----
+
The MAC address of the pod must appear on the bridge port that OVN-Kubernetes
created for the localnet.

. Confirm that OpenPERouter advertises the pod MAC and IP in EVPN:
+
[source,terminal]
----
$ oc exec -n openperouter-system <router-pod> -c frr -- \
    vtysh -c 'show bgp l2vpn evpn route type 2'
----
+
The Type-2 routes must include the pod MAC address and the
`192.170.1.10` and `192.170.1.20` bindings.

[NOTE]
====
The Linux bridge NAD in the `linux-bridge/` reference configuration sets
`disableContainerInterface: true`. It does not give a pod a usable interface
and is intended for virtual machines only. Use an OVN-Kubernetes localnet NAD
for pods.
====
